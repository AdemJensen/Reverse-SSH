创建专用 SSH 转发账号

在你管理的 Ubuntu 或 Debian 公网服务器上，创建一个用密码连接的账号，只允许它将指定的服务器端口反向转发到本机。

创建系统账号

在已安装 OpenSSH Server 的服务器上，用现有管理员会话操作。保留这个会话，直到确认重载后仍能用管理员账号另开连接。

为 tunnel 设置独立的强密码。以下命令创建系统账号及同名组，省略家目录，并将登录 shell 设为 nologin。

sudo useradd -r -U -M -d /nonexistent -s /usr/sbin/nologin tunnel
sudo passwd tunnel

如果 tunnel 已存在，先确认它确实是专用账号。命令选项可查阅 Debian useradd(8)。

限制 SSH 权限

编辑 /etc/ssh/sshd_config。把下面的块放在全局设置末尾、现有 Match 块之前。如果 Include 文件中已有适用于此账号的匹配规则，也要检查生效顺序。同一项在多个匹配块中出现时，先匹配到的值生效。Debian sshd_config(5)

Match User tunnel
    AuthenticationMethods password
    PasswordAuthentication yes
    KbdInteractiveAuthentication no
    MaxSessions 0
    AllowTcpForwarding remote
    PermitListen 127.0.0.1:18080
    GatewayPorts no
    ClientAliveInterval 30
    ClientAliveCountMax 3
    AllowStreamLocalForwarding no
    AllowAgentForwarding no
    X11Forwarding no
    PermitTunnel no
    PermitTTY no
    PermitUserRC no
  • MaxSessions 0 拒绝登录 shell、远程命令和 SFTP 等子系统，同时允许转发。
  • AllowTcpForwarding remote 只允许 SSH 的远程 TCP 转发，也就是 -R。PermitListen 限定服务器监听端点，客户端仍决定要把流量转到哪里。
  • GatewayPorts no 把监听限制在服务器的回环地址，适合宿主机上的 Nginx 或 Caddy。客户端要明确请求 127.0.0.1:18080。省略监听地址时，OpenSSH 请求的 localhost 与这条许可不同。
  • 客户端断网或休眠时，服务器可能仍保留旧 SSH 连接和它占用的远端监听端口。ClientAliveInterval 30 让服务器在 30 秒未收到客户端数据时发起保活探测。ClientAliveCountMax 3 把连续无响应的探测次数限制为 3。服务器判定连接失效后会关闭旧连接并释放端口，通常需要约一两分钟，具体取决于探测时序。OpenSSH 服务端保活手册
  • 需要监听服务器的特定网桥或其他非回环地址时，可为 tunnel 使用 GatewayPorts clientspecified。客户端用 -R 指定监听地址，PermitListen 限定允许请求的地址和端口。修改后要重新连接，让客户端发出新的监听请求。OpenSSH GatewayPorts 手册

保留已有的全局密码、账号和 PAM 策略。DisableForwarding yes 会覆盖转发许可，如果它对 tunnel 生效，先核对服务器的预期管理策略。OpenSSH 监听许可说明

检查并重载

先检查语法，再用 -T -C 检查 tunnel 的实际生效配置。若现有规则依赖来源地址、客户端主机名或服务器监听端口，把示例的连接参数换成实际值。

sudo /usr/sbin/sshd -t
sudo /usr/sbin/sshd -T -C 'user=tunnel,host=client.example.com,addr=203.0.113.25,laddr=192.0.2.10,lport=22' \
  | grep -Ei '^(authenticationmethods|passwordauthentication|kbdinteractiveauthentication|maxsessions|allowtcpforwarding|permitlisten|gatewayports|disableforwarding|clientaliveinterval|clientalivecountmax) '

确认输出包含 authenticationmethods password、passwordauthentication yes、maxsessions 0、allowtcpforwarding remote、clientaliveinterval 30 和 clientalivecountmax 3，并且 disableforwarding 为 no。默认回环方案应显示 permitlisten 127.0.0.1:18080 和 gatewayports no。选择下方的其他监听地址时，用对应值核对这两项，确认后再重载。

sudo systemctl reload ssh

保活设置对重载后建立的 SSH 连接生效。重载完成后重新连接隧道，即可使用新设置。

如果密码认证未通过，先看 sudo journalctl -u ssh -n 50 --no-pager。即使不请求 shell，账号仍须满足该机器的密码状态和 PAM 账号检查。服务器若启用了 pam_shells，而 nologin 不在其认可的 shell 列表中，认证可能被拒绝。按现有管理策略为专用账号处理，保留 PAM 检查。

Debian sshd(8)Ubuntu OpenSSH 指南Ubuntu pam_shells(8)

连接与验证

先在运行 Reverse SSH 的电脑上启动监听 127.0.0.1:3000 的 HTTP 服务。替换 server.example.com 为服务器的真实地址。首次连接时核对服务器的主机指纹。

在应用里填写上表并点击「连接隧道」，也可以在本机终端用下面的 OpenSSH 命令验证。两种方式择一，切换前先关闭已有隧道，释放服务器上的监听端口。若 SSH 端口不为 22，在命令中加上实际的 -p 参数。

ssh -NT -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -R 127.0.0.1:18080:127.0.0.1:3000 tunnel@server.example.com

-NT 让连接只做转发，保持命令运行即可。ExitOnForwardFailure 能发现远端监听建立失败，实际服务还要单独验证。Debian ssh(1)

隧道连上后，在服务器的管理员会话中访问远端监听端口，应收到本机服务的 HTTP 响应。专用账号禁止 SSH 本地转发，应用里的远端回环预览和检测会被拒绝，请以服务器上的检查为准。

curl -i --max-time 10 http://127.0.0.1:18080/

另开一个本机终端，测试专用账号是否拒绝执行远程命令。输入密码后应看到 SSH 拒绝打开会话，服务器不应返回 id 命令的输出。

ssh -T tunnel@server.example.com id

Docker 网桥里的 Nginx

如果宿主机上只监听 127.0.0.1:18080 或 [::1]:18080，Docker 网桥容器通过宿主机网关也访问不到这个端口。容器有自己的回环地址，宿主机网关则是另一个地址。Nginx 或 Caddy 直接运行在宿主机上时，继续使用上面的回环方案即可。Docker 网桥网络说明

在服务器上查看 Nginx 容器所在网络的网关，将下列示例中的 nginx 换成实际容器名。假设查到宿主机网桥地址为 172.17.0.1。如果宿主机配置的网桥地址不同，后面的 SSH 许可、远端监听和 Nginx 上游都要一起替换。

docker inspect --format '{{range $name, $network := .NetworkSettings.Networks}}{{println $name $network.Gateway}}{{end}}' nginx

只在现有的 Match User tunnel 块里替换这两项，保留 AllowTcpForwarding remote 和账号的其他限制。

    PermitListen 172.17.0.1:18080
    GatewayPorts clientspecified

按上文检查并重载 SSH，核对生效的 permitlisten 与 gatewayports。断开旧隧道，在 Reverse SSH 中把「远端监听」改为 172.17.0.1:18080 后重新连接。也可以在本机运行下列命令。

ssh -NT -o ExitOnForwardFailure=yes -R 172.17.0.1:18080:127.0.0.1:3000 tunnel@server.example.com

这里沿用前文的本机 HTTP 端口 3000。如果你的本机服务监听 8080，在应用中只修改「本地端口」，或在命令里只修改 -R 的最后一项。服务器的监听端口和 Nginx 上游端口仍是 18080。

在服务器上运行下面的命令，确认 Local Address:Port 显示 172.17.0.1:18080。如果还是只有回环地址，核对匹配规则和客户端的远端监听配置，并确认查看的是重连后的监听。

ss -ltn 'sport = :18080'

把容器内 Nginx 的上游改为相同地址。在容器里验证能访问这个端口，再重载 Nginx。如果你用 host.docker.internal 配合 host-gateway，也要确认它解析到同一个地址。Linux 上该别名默认使用 Docker 默认网桥的宿主机地址。Nginx proxy_pass 手册 Docker host-gateway 说明

proxy_pass http://172.17.0.1:18080;

将监听保持在指定网桥地址。公网只开放 Nginx 的入口，无需发布或对公网开放 18080。其他能到达此网桥的容器仍可能访问该端口，可用专用网桥和宿主机防火墙限制来源。

可选的公网 IPv4 监听

如果其他主机要直接访问 TCP 18080，在同一个 Match User tunnel 块里替换这两行。验证并重载后，把应用的远端监听地址改为 0.0.0.0，端口维持 18080，再重新连接。

    PermitListen 0.0.0.0:18080
    GatewayPorts clientspecified

0.0.0.0 会监听服务器的所有 IPv4 接口。将云安全组与系统防火墙的入站许可限制在需要访问的来源 IP 或网段，并用服务器的真实 IPv4 地址或域名访问该端口。OpenSSH GatewayPorts 说明

发布 Web 服务时，可以保留原来的回环监听，由同台服务器的 Caddy 提供 HTTPS。继续配置公网 HTTPS
