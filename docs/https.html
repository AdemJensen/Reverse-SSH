通过 Caddy 配置公网 HTTPS

让同一台 SSH 服务器上的 Caddy 接收 HTTPS 请求，再经 Reverse SSH 隧道访问你电脑上的 Web 服务。

本页内容

  1. 建立回环隧道
  2. 准备域名与入站端口
  3. 配置 Caddy
  4. 验证与排错

建立回环隧道

你需要一台自己管理的 Ubuntu 或 Debian 公网服务器、一个可管理 DNS 的域名，以及本机正在运行的 HTTP 服务。本文用 app.example.com 表示你要发布的网站域名。

在 Reverse SSH 中设置服务器监听 127.0.0.1:18080，转发到本机 127.0.0.1:3000。如果还没有专用 SSH 账号，可以先创建专用 SSH 转发账号。

  1. 浏览器https://app.example.com
  2. 公网服务器Caddy :443 → 127.0.0.1:18080
  3. 本机服务SSH 隧道 → 127.0.0.1:3000

连接后，在服务器的管理会话中先确认能经隧道访问本机服务。

curl -i --max-time 10 http://127.0.0.1:18080/

准备域名与入站端口

  • 把域名的 A 记录指向这台服务器的公网 IPv4。只有服务器具备可用的公网 IPv6，且能通过 IPv6 访问 Caddy 时，才为这个域名添加 AAAA 记录。检查并修正已有的错误记录。
  • 在系统防火墙和云安全组中允许 Caddy 的公网 TCP 80、TCP 443，并保证流量到达这台服务器。80 用于默认的 HTTP 跳转和 HTTP 验证，443 用于 HTTPS 及可用的 TLS 验证。
  • 远端监听 18080 保持在 127.0.0.1。Caddy 在同一台服务器访问它，公网入口是 Caddy。

配置 Caddy

把 Caddy 安装到 SSH 服务器上。官方 Debian 和 Ubuntu 软件包会安装并启动 caddy 服务。若 Nginx 或 Apache 已在宿主机上提供 HTTPS，可让现有服务反代到 127.0.0.1:18080。Caddy 官方安装步骤

如果 Nginx 运行在单独的 Docker 网桥容器中，其回环地址属于容器自身。可以让隧道只监听宿主机的网桥地址，再将 Nginx 的上游指向该地址。Docker 网桥中的 Nginx 配置

用 sudoedit /etc/caddy/Caddyfile 编辑现有配置，为你的真实域名新增站点块。如果该域名已有站点块，在现有块内调整反代设置。

app.example.com {
    reverse_proxy 127.0.0.1:18080
}

确认上面的域名已替换且 DNS 正确。验证配置成功后，重载服务。

sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile && sudo systemctl reload caddy

Caddy 在公网网站上终止 TLS，自动申请并续订证书。Caddy 到服务器回环监听这一段走 HTTP，随后经 SSH 隧道加密传输到本机。对公开服务，仍需在应用或代理层设置合适的登录和访问权限。

验证与排错

保持 Reverse SSH 和本机服务运行。从公网可访问的另一台设备打开实际域名，确认 HTTPS 证书可通过验证，页面来自预期的本机服务。

curl -i --max-time 15 https://app.example.com/
  • 证书未签发。先检查 A、AAAA、公网 80 和 443 端口，以及是否有其他 Web 服务器占用入口。查看 sudo journalctl -u caddy -n 60 --no-pager 获取验证错误。
  • Caddy 返回 502。回到 SSH 服务器再次检查 http://127.0.0.1:18080/。如果收不到预期响应，检查隧道是否连接、本机端口是否在监听，以及 Caddyfile 的上游端口是否一致。
